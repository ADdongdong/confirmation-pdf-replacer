## 一、项目背景

### 1.1 业务场景

券商（投行）从多家会计师事务所批量收到**往来款项/交易询证函** PDF，需要用券商标准话术重写函证头部内容，保留下方科目表格数据不变。

**核心需求：**

| 要素 | 来源 | 说明 |
|------|------|------|
| 标题 | 模板（固定） | 统一为"企业询证函" |
| 收函单位 | **原PDF自动提取** | 每家被审计单位不同，提取后保持原文 |
| 函证正文 | 模板（固定） | 券商标准话术 |
| 联系方式 | 模板（固定） | 项目联系人、电话、收件人、收件人电话、邮箱 |
| 索引号/编号 | **清除** | 白化覆盖后不重写 |
| 下方表格 | **原样保留** | 不修改 |

### 1.2 技术栈

| 层 | 技术 | 说明 |
|----|------|------|
| Web 服务 | Python Flask | 端口 8888，单文件 `web_form_server.py` |
| PDF 处理 | PyMuPDF (fitz) + pdfplumber | `replace_header_v4.py` |
| 前端 | 纯 HTML/CSS/JS | 单页应用 `templates/upload.html` |
| 配置持久化 | JSON 文件 | `python/configs/` 目录 + `_default.txt` |
| 字体 | NSimSun.ttf + SimHei.ttf | 宋体正文 + 黑体加粗 |

### 1.3 设计原则

- **单页操作**：所有功能（配置编辑 + 批量上传 + 生成下载）集中在 `/upload` 一个页面
- **默认配置自动加载**：进入页面自动从 `/config/default` 获取默认模板，填入表单
- **配置面板默认折叠**：日常操作只需上传 PDF → 生成，配置修改点击展开即可
- **覆盖区域可选强制/自动**：保存配置时可选择"使用自动值"（每个 PDF 独立检测）或"强制此值"（统一覆盖下界）

## 四、配置管理

### 4.1 配置 JSON 结构

存储路径：`python/configs/{安全名称}.json`

```json
{
  "name": "开源证券-默认模板",
  "body_text": "本公司聘请的XX证券股份有限公司正在对本公司进行尽职调查...",
  "contacts": {
    "项目联系人": "张三",
    "项目联系人电话": "13800138000",
    "收件人": "开源证券投行部",
    "收件人电话": "0755-88888888",
    "邮箱": "touhang@kzq.com.cn"
  },
  "whiteout_bottom": 318.5
}
```

- `name`: 配置显示名称
- `body_text`: 函证正文（最长 300 字，会在 PDF 中自动 CJK 断行）
- `contacts`: 联系方式 5 字段
- `whiteout_bottom`: 覆盖下界 Y 坐标（单位 pt），`null` 表示"自动检测"
- `is_default` 不存于 JSON 中，默认配置通过 `configs/_default.txt` 记录

### 4.2 默认配置机制

- 文件：`python/configs/_default.txt`（仅存一行：默认配置的安全文件名，不含 `.json`）
- 多个配置可共存，但只有一个默认
- 页面加载时调用 `GET /config/default` 自动获取
- 保存配置时勾选"设为默认配置"即写入 `_default.txt`

### 4.3 配置 API

| 路由 | 方法 | 功能 |
|------|------|------|
| `/config/default` | GET | 返回默认配置 JSON（含 `config` 对象） |
| `/config/list` | GET | 返回所有配置列表 `[{filename, name, body_text, has_whiteout}]` |
| `/config/load/<filename>` | GET | 加载指定配置完整内容 |
| `/config/save` | POST | 保存配置（JSON body），可选设为默认 |
| `/config/delete/<filename>` | DELETE | 删除配置，若是默认则清除 `_default.txt` |
| `/config/preview` | POST | 上传样本 PDF → 返回预览 PNG URL + 表格保护线 Y + 推荐白化下界 |

## 五、收函单位自动提取

### 5.1 提取策略（`extract_recipient()`）

搜索区域：PDF 首页 y ∈ [50, 300] 范围，逐行构建文本

| 优先级 | 策略 | 触发条件 | 提取方式 | 置信度 |
|--------|------|----------|----------|--------|
| 1 | "单位：" | 行内包含 "单位：" | 提取冒号后整行，trim | high |
| 2 | "致：" | 行内包含 "致：" | 提取冒号后整行，trim | high |
| 3a | "敬启者" 同行 | 行内包含 "敬启者" | 取"敬启者"之前的文本 或 之后的文本（去除标点）| high |
| 3b | "敬启者" 邻行 | 同行未找到公司名 | 向前后各 ±3 行搜索符合公司名特征的行 | medium |
| 4 | 兜底 | 以上全未找到 | 取搜索区域内第一个符合公司名特征的行 | medium |
| — | 全部失败 | 无符合特征文本 | 返回空字符串 | low |

### 5.2 公司名特征判断（`_is_likely_company_name()`）

- 长度：4~30 个字符
- 中文占比 ≥ 50%，且至少 4 个中文字符
- 排除关键词：`单位：`、`致：`、`敬启者`、`编号：`、`索引`、`询证函`、`会计师`、`审计`、`列示`、`余额`、`项目联系人`、`回函地址`、`收件人`、`邮编`、`邮箱`、`电话`、`传真`

### 5.3 前端置信度展示

| 后端返回 | 前端归类 | 标签文本 | 输入框样式 |
|----------|----------|----------|-----------|
| `high` | 已识别 | ✅ 已识别 | 绿色边框 `.high` |
| `medium` | 已识别 | ✅ 已识别 | 绿色边框 `.high` |
| `low` | 需确认 | ⚠ 需确认 | 黄色边框 `.low`，placeholder 提示输入 |

## 六、PDF 处理引擎

### 6.1 处理入口（`process_from_data()`）

```python
process_from_data(input_path, output_path, company_name, body_text,
                  contacts, font_file=None, whiteout_bottom=None, verbose=False)
```

参数说明：
- `company_name`: 收函单位名称（前端可手动修改）
- `body_text`: 函证正文（来自模板配置或前端实时输入）
- `contacts`: 联系方式 dict（5 字段）
- `whiteout_bottom`: 覆盖下界 Y 坐标（None 表示自动检测）
- 返回值：`(success: bool, message: str)`

### 6.2 处理流程

```
Step 1: extract_format() 提取原 PDF 格式参数
    ├─ 正文/标题字号统计（y∈[50,270] 区域）
    ├─ 左边距、段落宽度
    ├─ 行间距（相邻行 y 差值的均值）
    └─ 表格起始 Y（_find_table_start: 检测"列示如下"等关键词）

Step 2: 构建替换内容
    ├─ 头部: [('title','企业询证函'), ('body','致：{收函单位}'), ('body','　　{正文}')]
    ├─ 提示行: "若您方有相关本询证函函证事项问题，请直接联系下方项目联系人电话："
    └─ 联系方式: 两栏布局 [('pair', 项目联系人, 项目联系人电话), ('pair', 收件人, 收件人电话), ('single', 邮箱)]

Step 3: process_page() 双阶段执行
    │
    ├── Phase 1: 布局计算 ──────────────────────
    │   ├─ 标题行: y=48, 居中, title_fs 字号
    │   ├─ 收函单位行: 左对齐, body_fs 字号
    │   ├─ 正文行: wrap_cjk_text() 手动断行, body_fs 字号
    │   ├─ 提示行: wrap_cjk_text() 断行, body_fs 字号 (后续加粗)
    │   ├─ 联系方式: 两栏布局 (COL_GAP=20pt)
    │   │   ├─ 左栏: col_width = (para_w - 20) / 2
    │   │   └─ 右栏: right_x = left + col_width + 20
    │   └─ 白化下界: min(内容最底端+30, table_y-3)
    │
    └── Phase 2: 执行绘制 ──────────────────────
        ├─ add_redact_annot(Rect(0,0,page_w,whiteout_bottom), fill=white)
        ├─ apply_redactions() 一次性白化
        ├─ insert_font(NSimSun) + insert_font(SimHei)
        ├─ 逐块 insert_textbox() 写入文字
        │   ├─ 标题/正文: fontname=NSimSun
        │   ├─ 提示行: fontname=SimHei (真加粗) 或 NSimSun 偏移0.5pt (伪加粗)
        │   └─ 联系方式: fontname=NSimSun
        └─ doc.save(output_path, garbage=4, deflate=True)
```

### 6.3 表格保护线（`_find_table_start()`）

在 y > 250 区域搜索关键词确认表格起始位置：

| 关键词 | 说明 |
|--------|------|
| `往来余额`、`往来款项`、`列示如下`、`余额列示`、`往来账项` | 直接匹配 |
| 数字序号起始行（正则 `^\d+[\.\s、]`） | 兜底匹配 |

找到后返回 `y - 3`（在该行上方留 3pt 间隙），白化区域不得超过此线。

### 6.4 CJK 手动断行（`wrap_cjk_text()`）

避免 PyMuPDF 自动换行时标点错位问题：
- 全角字符宽度 = fontsize（1 em）
- 半角 ASCII 宽度 = fontsize × 0.55
- 逐字符累加宽度，超出 paragraph width 时断行

### 6.5 字体查找顺序

| 字体 | 用途 | 查找路径（按优先级） |
|------|------|---------------------|
| NSimSun | 正文/宋体 | `fonts/NSimSun.ttf` → `C:\Windows\Fonts\simsun.ttc` |
| SimHei | 加粗/黑体 | `fonts/simhei.ttf` → `C:\Windows\Fonts\simhei.ttf` → `fonts/simfang.ttf` → `C:\Windows\Fonts\simfang.ttf` |

> 注意：`simsunb.ttf` 实际是 SimSun-ExtB（扩展字符集），缺少常用汉字，仅在无其他黑体时作为最后回退。

## 七、批量处理 API

### 7.1 批量上传（`POST /batch/upload`）

- 入参：`multipart/form-data`，字段 `pdf_files`（可多个）
- 限制：单次最多 20 个文件
- 处理：逐文件调用 `extract_recipient()` + 生成 72 DPI 缩略图
- 返回：
```json
{
  "success": true,
  "token": "a1b2c3d4e5f6",
  "files": [{
    "id": "abc12345",
    "name": "立信函证.pdf",
    "recipient": "A公司",
    "confidence": "high",
    "previewUrl": "/batch/preview/a1b2c3d4e5f6/thumb_abc12345.png"
  }]
}
```
- 会话存储：`_batch_sessions[token]` 字典（内存，服务重启丢失）

### 7.2 批量生成（`POST /batch/generate`）

- 入参（JSON）：
```json
{
  "token": "a1b2c3d4e5f6",
  "body_text": "...",
  "contacts": { "项目联系人": "...", ... },
  "recipients": { "abc12345": "A公司", "def67890": "B公司" },
  "whiteout_bottom": 318.5
}
```
- `whiteout_bottom` 为 `null` 时后端自动检测
- `recipients` 覆盖前端手动修改的收函单位（优先于自动提取值）
- 输出：逐份处理 → 打包为 `hanzheng_batch_{token}.zip`
- 返回：`{ success, downloadToken, total, errors }`

### 7.3 重新识别（`POST /batch/re-recognize`）

- 入参（JSON）：`{ token, fileId }`
- 重新调用 `extract_recipient()` 更新该文件的识别结果
- 返回：`{ success, recipient, confidence }`

### 7.4 批量下载（`GET /batch/download/<token>`）

- 返回 ZIP 文件（`Content-Type: application/zip`）
- 文件名：`hanzheng_batch_{token}.zip`

### 7.5 会话生命周期

- 上传时创建 session token（12 位 hex）
- 生成时读取 session 中的文件路径
- 下载后 session 保留（支持重复下载）
- 服务重启后所有 session 和临时文件丢失

## 八、覆盖区域校准

### 8.1 设计目的

不同会计师事务所的函证格式各异（标题位置、正文行长、表格起始行不同），需要确定 PDF 首页从顶部到哪个 Y 坐标之间的区域需要"白化覆盖"。

### 8.2 双重模式

| 模式 | whiteout_bottom 值 | 批量处理行为 |
|------|-------------------|-------------|
| 自动检测（默认） | `null` | 每个 PDF 各自调用 `process_page()` 计算布局，自动确定白化下界 |
| 强制指定 | 具体数值（如 318.5） | 所有 PDF 统一使用此 Y 坐标作为白化下界 |

### 8.3 交互流程

```
点击 ⚙修改配置 展开面板
  → 子区域1: 覆盖区域校准
    → 上传一份代表性格式的会所函证 PDF
    → POST /config/preview 返回:
        - 首页 PNG 预览图 (150 DPI)
        - pageWidth, pageHeight (PDF 坐标空间)
        - tableY (表格保护线)
        - autoWhiteoutBottom (推荐白化下界: tableY - 3, 上限 55% 页面高)
    → 前端渲染预览图 + 红色半透明遮罩 + ≡ 拖拽手柄 + 绿色保护线
    → 鼠标/触摸拖动手柄调整白色覆盖下界 (范围: [48, tableY-5])
    → 点击 [强制此值] → 拖拽值生效; [使用自动值] → 恢复推荐值
    → 保存配置时：forceWhiteout=True → 写入数值; False → 写入 null
```

### 8.4 覆盖值在批量生成时的优先级

```
submitBatch() 中:
  ┌─ forceWhiteout=true 且 previewData 存在 → 使用实时拖拽值
  └─ 否则 → 使用 configWhiteoutBottom (配置中保存的值，可能为 null)
      └─ null → 后端各 PDF 独立自动检测
```

## 十、附：原 Java 版本说明

项目早期设计中包含 Java 版本（`java/` 目录），使用 PDFBox 实现相同功能。Python 版本是目前的主力实现，两个版本的核心逻辑保持一致：

- 同为 `extract_format()` + 布局计算 + 白化 + 重写两阶段流程
- 同用 NSimSun + SimHei 字体
- 同以表格保护线控制白化下界
- Python 版额外支持：CJK 手动断行、批量会话管理、Web 配置持久化

Java 版保留作为 CLI 工具和备选方案。
