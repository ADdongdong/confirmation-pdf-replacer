## 函证PDF头部替换工具 v3 开发

- 用户反馈核心需求：保留会所原格式（字体/字号/段落宽度），仅替换文字内容
- 分析确认会所PDF使用 NSimSun 字体，正文 10.5pt（五号），段落宽度 536pt
- v3 核心改进：
  - 自动从原PDF提取格式参数（字体、字号、边距、行距），不需用户JSON配置
  - 用户只需提供纯文本文件（带 TITLE:/RIGHT: 标记），按原格式渲染
  - 自动预估长文本行数并动态分配 rect 高度，防止 insert_textbox 换行导致重叠
  - 字体明确嵌入 NSimSun（从 fonts/NSimSun.ttf 读取）
- 测试结果：13/13行成功写入，无重叠，表格数据完整保留（64行）
- 话术文件：configs/broker_home.txt（命令行参数 -t 指定）
- 用法：`python replace_header_v3.py <会所PDF> -t <话术.txt> -o <输出.pdf>`

## 函证PDF头部替换工具 v4 开发

- 用户反馈 v3 效果差，要求重新设计方案：
  - 顶部固定头部 → 白化后按原格式重写
  - 联系方式区（项目联系人/电话/回函地址/收件人/邮箱）→ 原位文本替换
- v4 核心改进：
  - **分区域处理**：话术文件用 `---` 分隔头部和联系方式两区
  - **手动 CJK 断行**：`wrap_cjk_text()` 按字符宽度预估断行，避免 PyMuPDF 自动换行的标点错位
  - **统一白化**：从 y=0 到联系方式结束区域一次白化，避免多次 apply_redactions 冲突
  - **表格保护线**：自动检测"列示如下"行的 y 坐标作为白化下界，杜绝覆盖表格引导行
  - **联系方式紧凑布局**：根据可用空间自动计算行间距（最小12pt），6行联系方式全部装入
- 测试结果：13/13行成功（头部7子行+联系方式6行），无头部重叠，64行表格完整保留
- 话术文件：configs/broker_home_v4.txt
- 用法：`python replace_header_v4.py <会所PDF> -t <话术.txt> -o <输出.pdf>`
- 已知：底部页脚（索引号/编号）残留，不在替换范围内

## Web 表单系统开发

- 用户要求提供网页表单界面，替代手工编辑配置文件：
  - 函证说明部分（正文文本，限制250字符）→ 输入框
  - 项目联系人 → 独立字段
  - 项目联系人电话 → 独立字段
  - 收件人 → 独立字段
  - 收件人电话 → 独立字段
  - 邮箱 → 独立字段
  - 函证编码和索引号 → 不展示，自动生成（HZ/LC + 时间戳）
  - 回函地址 → 不再显示（用户未列此字段）
- 新增文件：
  - `web_form_server.py` — Flask Web 服务器（端口8888），路由 `/`（表单）和 `/generate`（处理）
  - `templates/index.html` — 响应式表单页面，含字数统计、拖拽上传、示例模板、结果下载
- `replace_header_v4.py` 新增 `process_from_data()` 函数：直接从结构化数据（company_name, body_text, contacts_dict）生成PDF，供 Web 服务器调用
- 端到端测试：12/12行成功，Web服务正常运行
- 用法：`python web_form_server.py` → 浏览器访问 http://localhost:8888
