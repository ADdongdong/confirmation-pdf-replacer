## 业务场景澄清 + 批量处理设计

### 业务场景（用户最新描述）
- 用户（券商/投行）会从多家会计师事务所批量收到函证 PDF
- 每份 PDF 的「函证正文」「联系方式」「待替换区域」**内容是固定的**（用同一套标准话术）
- **每份 PDF 都有自己的「收函单位」**（被审计单位，如 "A公司"），这个要保留原文，不能覆盖
- 期望：一次上传 N 个 PDF → 自动识别每家的收函单位 → 批量生成

### 关键修正（避免之前混淆的概念）
- ❌ **不是提取"制函单位"（会计师事务所名）**——制函单位是固定写死的，不需要每份不同
- ✅ **要提取的是"收函单位"（被审计单位）**——出现在「单位：XXX」这一行，例如 "A公司"
- 原 PDF 中的位置：标题"往来款项/交易询证函"下方，"单位：A公司"这一行
- 当前 Java 代码的 `致：companyName` 需要改成 `单位：[自动提取的收函单位]`

### 标题修正
- 原 PDF 标题不是硬编码的"企业询证函"，实际是 **"往来款项/交易询证函"**
- 后续可能还有其他标题变体，需要保留或作为模板字段

### 设计方案（两阶段操作）

#### 阶段一：模板设置（一次性）
固定内容：标题模板、正文话术、联系方式（联系人/电话/收件人/电话/邮箱）
模板存储：`templates/*.json`，服务端保存/加载

#### 阶段二：批量处理（反复用）
```
拖入N个PDF → 后端自动识别每份的"单位：XXX"收函单位
  → 文件列表展示（每行可手动修改收函单位）
  → 用户点"全部生成"
  → 后端逐份处理：用模板 + 各自收函单位重写头部
  → ZIP 打包下载
```

### 自动提取"收函单位"策略
1. **首选**：在 y ∈ [50, 200] 文本行中查找 "单位：" 关键字，提取其后内容
2. **兜底**：取标题下方首个独立文本行（4~20 字符）
3. **置信度低时**：列表中该行标红，要求用户手动确认

### 设计确认（2026-07-16 用户确认）

| # | 问题 | 确认结果 |
|---|------|----------|
| 1 | 标题 | **固定为"企业询证函"** |
| 2 | 索引号/编号 | **清除**（白化覆盖后不重写） |
| 3 | 收函单位关键字 | **多种可能**："单位："、"敬启者"、"致：" |
| 4 | 收函单位提取边界 | **取整行内容**，剔除空字符 |

### 收函单位提取逻辑（确认版）
在原文 y ∈ [50, 200] 区域逐行搜索：
1. 先找 "单位：" → 提取冒号后的整行文本
2. 没找到则找 "致：" → 提取冒号后的整行文本
3. "敬启者" 的情况 → 取附近长度 4~20 个中文字符的独立文本行
4. 全都没找到 → 返回空，前端红色标记，要求手动输入
5. 提取结果 trim() 去空字符

### 白化后输出格式
- 标题: `企业询证函`（固定）
- 收函单位行: `单位：{自动提取的收函单位名称}`
- 正文: 模板固定内容
- 联系方式: 模板固定内容
- 索引号/编号: 不写入（被白化清除）

### Mermaid 避坑要点（已写入 MEMORY.md）

- 含特殊字符的节点用双引号包裹
- `<br/>` 换行正常

### 问题
敬启者格式常见写法如 `某某科技有限公司 敬启者：`，原策略只在 ±2 行附近搜索独立行，且字符上限 20、y 搜索范围 [50,200] 过小，导致识别失败。

## 批量下载文件后缀缺失修复

### 问题
批量生成的 ZIP 中文件名为 `fixed_xxx_会所pdf1_pdf`，原本的 `.pdf` 被替换成了 `_pdf`，导致下载后无法打开。

### 根因
`web_form_server.py` 中生成输出文件名时：
```python
safe_name = "".join(c if c.isalnum() or c in '_- ' else '_' for c in f['name'])[:40]
```
原始文件名包含 `.pdf`，点号 `.` 被当成非法字符转成了 `_`。

### 修复
- 用 `os.path.splitext(f['name'])[0]` 先去掉扩展名，再对基础文件名做清洗
- 输出路径显式添加 `.pdf`：
  ```python
  base_name = os.path.splitext(f['name'])[0]
  safe_name = "".join(c if c.isalnum() or c in '_- ' else '_' for c in base_name)[:40]
  out_pdf = os.path.join(batch_out, f'fixed_{f["id"]}_{safe_name}.pdf')
  ```
- 服务已重启。

## 模板配置页开发

### 背景
用户要求将"覆盖区域选择"和"正文/联系方式填写"合并为一个持久化配置页面，配置后批量处理自动复用。

### 实现内容

#### 后端 API（`web_form_server.py`）
- `GET /config` → 配置管理页面
- `POST /config/preview` → 上传样本 PDF，返回预览图 + 自动检测 table_y + 推荐 whiteout_bottom
- `POST /config/save` → 保存配置 JSON 到 `configs/` 目录
- `GET /config/list` → 列出所有已保存配置
- `GET /config/load/<name>` → 加载指定配置
- `DELETE /config/delete/<name>` → 删除指定配置
- `GET /config/default` → 获取默认配置（批量页自动加载用）

#### 前端（`templates/config.html`）
- **步骤1**：上传样本 PDF → 预览 + 红色覆盖遮罩 + 拖拽调整 → 绿色线标记表格保护线
- **步骤2**：正文 + 联系方式表单 + 配置名称 + "设为默认"复选框
- 加载已有配置下拉列表，支持加载/删除
- 覆盖区域两种模式：`自动检测` (whiteout_bottom=null，每个 PDF 各自检测) / `强制此值` (所有 PDF 统一)

#### 批量页集成（`templates/batch.html`）
- 页面加载时自动请求 `/config/default`，预填模板正文 + 联系方式
- 生成时传递 `whiteout_bottom` 到后端
- 导航栏添加"模板配置"链接

#### 配置 JSON 格式
```json
{
  "name": "开源证券-默认模板",
  "body_text": "本公司聘请的...",
  "contacts": { "项目联系人": "张三", ... },
  "whiteout_bottom": null  // null=自动检测
}
```

### 设计决策
- `whiteout_bottom = null` 时，批量处理每个 PDF 各自自动检测表格位置（更安全，适配不同会所）
- `whiteout_bottom = 数值` 时，所有 PDF 统一使用该覆盖下界
- 默认配置文件 `_default.txt` 只存当前默认配置名，简洁可靠
